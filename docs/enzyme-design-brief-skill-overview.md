# Enzyme-Design-Brief Skill 功能与设计亮点

## 概述

`enzyme-design-brief` 是一个面向酶工程计算设计（dry-lab）的 AI-first 工作流 skill，将文献证据、计算模型和用户协同决策整合为一个可追溯、可复现的酶序列设计流程。

---

## 核心功能

### 四阶段工作流

```
Stage 0: 需求明确 → Stage 1: 证据收集 → Stage 2: AI 策略协同设计 → Stage 3: 计算执行
```

| 阶段 | 做什么 | 产生物 |
|------|--------|--------|
| **Stage 0** | 一次性筛选目标酶、参考序列、设计目标、权衡偏好 | 设计需求总结 |
| **Stage 1** | 6 通道并行文献探索 → 构建可溯源的证据档案 | 文献证据 dossier |
| **Stage 2** | 用户与 AI 协同设计 2-4 条计算路线，定义 masks、指标、决策门 | 设计 spec 文件 |
| **Stage 3** | 将 spec 转化为可执行的工作包，工具验证 → 执行 → 自适应迭代 | 计算计划 + 排名候选序列 |

### 证据溯源系统

每个重要声明必须标注来源标签：

| 标签 | 含义 |
|------|------|
| `EVIDENCE` | 引用文献、数据库或用户提供的数据 |
| `INFERENCE` | 基于证据的合理推断 |
| `MODEL_HYPOTHESIS` | 模型/分数/模拟产生的假设 |
| `CREATIVE_HYPOTHESIS` | LLM 或用户提出的创造性想法 |
| `DECISION` | 用户批准的约束、阈值或策略 |
| `OPEN_QUESTION` | 可能改变路线的缺失信息 |

**为什么重要**：在计算酶设计中，模型输出的分数不是事实。这个系统确保你始终知道每项设计决策的可靠性边界。

### 硬门禁：批准后才能执行

```
Stage 1/2 允许: 文献检索、本地分析、推理、计划编写
Stage 1/2 禁止: PLM 推理、MPNN 生成、AF2 预测、MD、Rosetta、骨架生成
```

**设计哲学**：在用户批准设计 spec 和计算计划之前，不运行任何昂贵的计算作业。避免"先跑再看"的浪费。

### 自适应决策循环

在执行前明确定义分支规则：

```text
PLM 突变扫描
  → 高分突变集中在可解释区域：细化 mask，运行 MPNN 生成
  → 分数分散/冲突：加入保守性和结构约束

结构预测
  → 折叠和催化几何通过：进入能量评分
  → 折叠通过但催化几何失败：收紧约束重新生成
  → 折叠广泛失败：缩小重设计范围或切换 scaffold
```

每个分支必须指明：输入、检查指标、阈值、下一步动作。

## 设计亮点

### 1. AI 是主引擎，不是附属品

传统酶设计通常以"文献综述 → 理性设计 → 实验验证"为主线，AI 方法被放在边栏。

本 skill 的核心哲学是：**AI 方法（PLM、MPNN、AlphaFold、Rosetta、MD）是候选序列生成和排序的主要机制**。文献提供约束和先验，但 AI 是真正的设计引擎。

具体体现在：
- Stage 1 的文献探索区分了"证据"和"AI 设计先验"两个维度
- Stage 2 要求 LLM 主动提出 2-4 条包含模型组合和混合策略的路线
- 自适应循环让模型输出反馈到下一轮设计决策

### 2. 一次一个问题，避免假设

Stage 0 和 Stage 2 的对话规则明确规定：**每次只问一个问题，在信息不足时不发明阈值**。

这避免了 AI 过早锁定不好的方向。例如在本会话中：
- 先确认参考酶（IsPETase vs LCC）
- 再确认目标温度（55-65°C vs 70-80°C）
- 再确认权衡偏好（稳定性优先 vs 活性同等）
- 最后才确认设计范围和路线选择

### 3. 多路线并行 + 计算成本阶梯

Stage 2 要求提出 2-4 条路线并保留被拒绝的替代方案。执行时遵循"廉价过滤器先于昂贵方法"原则：

```
PLM 扫描 (<1 min) → 序列过滤 (<1 min) → AF2 预测 (min-hr) → Rosetta (min-hr) → MD (hr-day)
```

### 4. 文献探索的 6 通道并行架构

Stage 1 将文献探索分解为 6 个独立维度，每个维度可以并行执行：

| 通道 | 范围 |
|------|------|
| function-boundary | 功能、底物范围、同源家族 |
| structure-mechanism | 催化残基、结构、动力学 |
| mutation-evidence | 正负突变、可转移性 |
| conditions-metrics | 定量测量、实验条件 |
| ai-design-priors | 计算方法、模型前例 |
| risk-gaps | 冲突、失败尝试、证据缺口 |

每个通道返回结构化发现和证据 ID，最后由 orchestrator 去重和综合。

### 5. 候选序列的结构化记录

每条生成的序列都有完整的谱系记录：

```json
{
  "candidate_id": "唯一 ID",
  "parent_id": "父序列 ID",
  "mutations": ["S121E", "D186H"],
  "provenance": ["EVIDENCE", "MODEL_HYPOTHESIS"],
  "generation": { "method": "ProteinMPNN", "version": "...", "seed": 42 },
  "metrics": { "plddt": 92.3, "ddG": -2.1 },
  "hard_filter_status": "pass",
  "decision": "retain"
}
```

### 6. 湿实验完全解耦

明确声明"不规划表达、纯化、湿实验筛选、测定或物理验证"。skill 边界清晰：只做 dry-lab 设计，输出是排名序列列表 + 完整计算元数据，交给实验团队验证。

## 适用场景

| 场景 | 描述 |
|------|------|
| 热稳定性工程 | 提升酶 Tm 而不丧失活性（如本次 PETase 案例） |
| 底物特异性改造 | 改变酶的底物偏好 |
| 活性位点重设计 | 优化催化效率 |
| 新 scaffold 发现 | 为已知催化 motif 寻找更好的骨架 |
| 多目标优化 | 同时优化稳定性、活性、溶解度、表达量 |

---

## 与其它 Skills 的关系

`enzyme-design-brief` 是最高层编排 skill。在它的工作流中会调用：

- `literature-explore` / `literature-workflow`：文献检索与综合
- `brainstorming` / `writing-plans`：Superpowers 风格的协同设计和计划编写
- 执行阶段可集成：`alphafold`、`proteinmpnn`、`esm`、`rfdiffusion`、`pyrosetta-scoring`、`openmm-md` 等

---

## 一句话总结

**将"帮我设计一个更稳定的酶"这个模糊需求，转化为一个 AI 驱动、证据可追溯、用户全程参与决策、最终产出排名候选序列的计算管线。**
