# IsPETase 热稳定性设计 — 会话案例

> 使用 `enzyme-design-brief` skill 完成一个完整的 AI-first 酶工程计算设计流程的真实案例。

---

## 场景

**需求**：设计 PET 水解酶（IsPETase），将热稳定性从野生型 Tm ~48°C 提升至 70-80°C，同时保持催化活性。

**用户输入只有一句话**：
> "使用 enzyme-design-brief skill，帮我设计 PET 水解酶，提高热稳定性"

---

## 会话流程

### 总耗时与规模

| 指标 | 数值 |
|------|------|
| 会话轮次 | ~8 轮 |
| 后台并行任务 | 7 个（6 文献通道 + 1 序列/结构查询） |
| 文献筛选 | ~135+ 篇论文 |
| 证据引用 | 30+ DOI/PMID |
| 最终产物 | 2 个文档（设计 spec 210 行 + 执行计划 345 行） |

### Stage 0: 需求明确（2 轮）

AI 逐次问了 4 个问题，而不是一次性抛出所有问题：

1. **哪个参考酶？** → IsPETase (Ideonella sakaiensis)
2. **目标温度？** → 70-80°C（wt Tm ~48°C）
3. **稳定性 vs 活性如何权衡？** → 同等重要
4. **设计范围？** → 无预设，由计算引导

每轮只问一个问题，避免用户疲劳，也避免 AI 在信息不全时做出错误假设。

### Stage 1: 证据收集（1 轮启动 + 后台等待）

AI 同时启动了 **7 个并行后台文献探索 agent**：

| 通道 | 探索内容 | 关键发现 |
|------|---------|---------|
| 功能边界 | 底物范围、同源家族、动力学 | IsPETase 是芳香族聚酯酶，不降解脂肪族聚酯 |
| 结构机制 | PDB 结构、催化三联体、动力学 | S160-D206-H237；缺乏 Ca²⁺ 结合位点是低 Tm 根源 |
| 突变证据 | 所有已报道的突变及其效应 | D186V +12.9°C；HotPETase Tm 80.5°C 但高温活性仅 3h |
| 条件与指标 | Tm 测量方法、标准 assay 条件 | 跨研究比较因方法不一致而不可靠（Nature Comms 2025） |
| AI 设计先验 | PLM、MPNN、Rosetta、MD 的应用前例 | GRAPE 策略直接用于 IsPETase；ESM-2 发现 KbPETase |
| 风险与缺口 | 失败案例、天花板、矛盾 | IsPETase 独立变体天花板 ~65-69°C |
| 序列/结构 | UniProt 序列、PDB 结构详情 | 成熟酶 263 aa，PDB 5XJH 是全残基建模的 WT 结构 |

每个通道返回结构化的证据档案（含 DOI/PMID），最后由 AI 综合为一份包含 5 大类、30+ 数据点的证据摘要。

**关键证据驱动的设计决策**：
- 文献明确显示 IsPETase 缺乏 Ca²⁺ 结合位点 → 这成为引入盐桥/二硫键策略的证据基础
- HotPETase 虽 Tm 达 80.5°C 但高温活性仅 3h → 稳定性≠操作稳定性，需 MD 验证
- IsPETase scaffold 天花板 ~65-69°C → 70-80°C 目标可能需要多路线并行推进

### Stage 2: AI 策略协同设计（2 轮）

AI 基于证据提出了 **3 条计算路线**：

| 路线 | 方法 | 定位 |
|------|------|------|
| **A** | ESM-2 全位点突变扫描 → MPNN 局部重设计 | PLM 引导 + AI 探索新突变 |
| **B** | 已知阳性突变组合 + 上位性检查 | 风险可控的累积策略 |
| **C** | 大规模 MPNN + MD 验证 | 激进的后备路线 |

每条路线都包含：生成方法、评分体系、计算成本、主要风险、触发 pivot 的条件。

用户选择了**三条路线全开**，AI 随即构建了完整的设计合同：
- 不可变/限制/可设计区域的详细 mask 定义
- 7 个硬过滤器 + 7 个排序信号的多目标 Pareto 排序体系
- 4 个自适应决策门（PLM 扫描后 → AF2 预测后 → 能量评分后 → MD 验证后）

### Stage 3: 计算执行计划（1 轮）

AI 将设计 spec 转化为 **12 个结构化工作包**，分为 4 个阶段：

```
Phase 0: 环境与工具验证 (1 WP)
Phase 1: 路线 A — PLM + MPNN 重设计 (5 WPs)
Phase 2: 路线 B — 累积突变 + 上位性检查 (5 WPs)
Phase 3: 路线 C — 大规模 MPNN + MD 验证 (4 WPs)
Phase 4: 整合排序与打包 (3 WPs)
```

每个工作包包含：目的、输入、方法（含具体命令）、输出、指标、QC 检查、决策门。

三条路线完全并行执行，Phase 4 在所有路线完成后启动。

## 为什么这是一个好案例

### 1. 展示了 skill 的完整四阶段工作流

从一句模糊需求到一份可执行的计算计划，完整覆盖了 skill 的全部能力范围。

### 2. 展示了并行证据收集的威力

7 个通道同时运行，从功能、结构、突变、条件、AI 方法、风险 6 个维度对同一酶进行了全面的文献审查。如果人工完成，至少需要数天。

### 3. 展示了 AI 如何推动设计决策

不是简单复述文献，而是：
- 从结构弱点（缺乏 Ca²⁺ 结合位点）推断出引入盐桥的策略
- 从天花板证据判断单一突变路线可能不够，提出多路线并行
- 识别出文献中的方法论危机，避免过度依赖跨研究比较

### 4. 展示了"一次一个问题"的对话纪律

用户没有被信息轰炸——每个设计决策都由前一步的证据自然引出。

### 5. 最终产物可以直接进入执行

345 行的执行计划包含具体命令、文件路径、QC 检查——不是概念性的"然后我们可以做 ML"，而是可以直接跑的工作包。

## 可复用的模式

如果你在自己的项目中参考这个案例：

1. **Stage 0 不要跳过**：花 2-3 轮澄清需求，比直接开始设计然后返工节省大量时间
2. **6 通道文献探索是标配**：对于任何非 trivial 的酶设计，至少需要函数、结构、突变三个维度的证据
3. **永远提供多条路线**：让用户（或你自己）在不同风险和成本之间做选择
4. **决策门要写在执行前**：不是"等结果出来再说"，而是"如果 X 发生，我们做 Y"
5. **记录 provenance**：在酶设计中，区分"文献已经验证的"和"模型预测的"至关重要——前者可以信赖，后者需要验证
