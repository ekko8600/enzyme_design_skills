# Enzyme-Design-Brief 技能工作流程演示

> **项目**: Proteinase K 热稳定性工程 (Tm ~65°C → ~80-85°C+)
> **对话日期**: 2026-05-31
> **技能路径**: `my_home/enzyme-design/`

---

## 一、技能概览

`enzyme-design` 是一个 **AI 驱动的干实验酶设计技能**，将酶工程需求转化为可执行的计算策略。它不规划设计湿实验（表达、纯化、筛选），专注于：

- 定义序列和结构约束
- 生成候选突变/序列/骨架
- 计算评分、过滤和排序
- 结构、动力学、能量学和多维度评估
- 迭代直到输出序列集满足约定的干实验标准

## 三、本次演示的具体执行过程

### Stage 0: 明确计算目标

通过**一问一答**式交互逐步收窄需求，避免一次性抛出过多问题。

| 轮次 | 问题 | 收集到的信息 |
|------|------|-------------|
| Q1 | 有哪些参考材料？ | 只有名称，无序列/结构/登录号 |
| Q2 | 热稳定性目标？ | 大幅提升（15-20°C 以上） |
| Q3 | 底物选择性要求？ | 保持广谱底物选择性不变 |
| Q4 | 设计契约确认？ | 同意（首轮1-3个突变，Rosetta+FoldX共识） |

**设计目标最终定义**:
```yaml
Target: Proteinase K (EC 3.4.21.64, Engyodontium album)
Goal: Tm +15-20°C (65°C → 80-85°C+)
Constraints:
  - Preserve catalytic triad D39-H69-S224
  - Preserve disulfide bonds C34-C123, C178-C249
  - Maintain broad substrate selectivity
  - Maintain enzymatic activity
```

### Stage 2: AI 优先协同设计

#### 2.1 设计契约 (残基分类)

蛋白质上每个位点都被赋予明确的"可变动级别"：

```
┌────────────────────────────────────────────────┐
│            Proteinase K 残基分类               │
├──────────┬─────────────────────────────────────┤
│ 🔒 不可变 │ D39, H69, S224  (催化三联体)       │
│          │ C34, C123, C178, C249 (二硫键)       │
├──────────┼─────────────────────────────────────┤
│ ⚠️ 受限  │ Ca²⁺ 配位残基 (可改但需补偿)         │
│          │ 底物结合口袋残基                     │
├──────────┼─────────────────────────────────────┤
│ 🟢 可设计│ 表面环区、β-转角、N端、C端、其余位点 │
└──────────┴─────────────────────────────────────┘
```

#### 2.2 路线选择: 提出 4 条策略供用户选择

| 策略 | 核心方法 | 风险 | 计算量 |
|------|---------|------|--------|
| 1 ⭐ | Rosetta ddG + ESM → 组合 → MPNN | 低 | 中 |
| 2 | Ca²⁺ 位点定向工程 | 高 | 高 |
| 3 | 同源酶引导 + 共识设计 | 中 | 中 |
| **4** ✅ | **全集成: 1+2+3 → Pareto 排名 → MD** | **中** | **最高** |

> 用户选择策略 4（最全面）

#### 2.3 评分矩阵

**7 个硬过滤** (任一不通过即淘汰)：

| # | 过滤项 | 方法 | 阈值 |
|---|--------|------|------|
| F1 | 全局折叠置信度 | AF2 pLDDT | ≥ 85 |
| F2 | 催化三联体几何 | Cα RMSD | ≤ 0.5 Å |
| F3 | 底物口袋几何 | Cα RMSD | ≤ 1.0 Å |
| F4 | 非预期二硫键 | Cα-Cα距离 | 无新增 |
| F5 | 原子冲突 | Rosetta fa_rep | ≤ WT+10 |
| F6 | 聚集热点 | Aggrescan | 无新增高风险 |
| F7 | 序列 liabilities | 模式匹配 | 0 新增 |

**12 个排名信号** (Pareto 多目标优化)：

```
权重分布:
  稳定性 (ddG/pLDDT/score): ████████░░ 35%
  活性保持 (RMSD/口袋):     ██████░░░░ 30%
  序列质量 (ESM/保守性):    ███░░░░░░░ 15%
  可开发性 (溶解/聚集):     ██░░░░░░░░ 10%
  多样性 (identity):        ██░░░░░░░░ 10%
```

#### 2.4 自适应决策环

管道不是线性的——每个阶段都定义了分支条件：

```
Phase 1 输出 (~100候选)
  ├→ Rosetta+ESM 评分集中于特定区域?
  │    是 → 扩大MPNN重设计范围
  │    否 → 增加保守性/接触约束 → 重新过滤
  │
Phase 2 输出 (通过硬过滤的候选)
  ├→ 通过率 ≥ 50%? → 进展到组合阶段
  ├→ 口袋几何普遍失败? → 收紧口袋约束
  ├→ pLDDT普遍失败? → 缩小到仅表面暴露位点
  │
Phase 3 输出 (组合 + MPNN)
  ├→ 加性效应? → 扩展到4-6突变
  ├→ 负上位效应? → 记录, 限制在2-3突变
  │
Phase 5 输出 (MD验证)
  ├→ RMSD稳定 + 活性位点保持? → 最终候选
  ├→ 某区域反复不稳定? → 回到Phase 1重扫
  └→ 与WT行为相似? → 降级排名, 标记不确定性
```

## 四、技能特色

### 1. 证据溯源 (Provenance Tracking)

每一条重要声明都带有溯源标签，区分事实与推测：

| 标签 | 含义 | 示例 |
|------|------|------|
| `EVIDENCE` | 有文献/数据库支持 | "D260V: 12.4× t₁/₂" |
| `INFERENCE` | 基于证据的合理推论 | "CM16突变可映射到PRK" |
| `MODEL_HYPOTHESIS` | 模型预测/评分结果 | "Rosetta预测 ΔΔG = -2.3" |
| `CREATIVE_HYPOTHESIS` | LLM/用户提出的设计想法 | 新型补偿性H键设计 |
| `DECISION` | 用户批准的策略选择 | "选择策略4" |
| `OPEN_QUESTION` | 缺失信息需解决 | "可用GPU时数?" |

### 2. 硬门禁 (Hard Gate)

**批准前不执行任何计算任务。** 只有设计规约和执行计划都被用户批准后，才允许运行 GPU 任务。如果一个模型输出揭示新信息，可以回到 Stage 2 修订路线。

### 3. 多通道并行文献检索

不是一次查询，而是 **将研究请求分解为 6 个独立通道**，每个通道由专用代理并行执行，各自返回结构化 JSON 证据。调度器负责合并、去重、冲突保留、深度合成。

### 4. 逐段确认的协同设计

Stage 2 不是一次性输出整个方案，而是**逐步呈现**：
设计契约 → 路线选择 → 管道定义 → 评分矩阵 → 决策环 → 最终确认

每个环节都等待用户反馈，允许调整和修订。

### 5. 自适应决策环

管道不是写死的脚本，而是包含 **条件分支和回退机制**：
- 如果某阶段通过率低，自动缩小搜索空间
- 如果组合出现负上位效应，记录并限制突变数
- 如果 MD 揭示持续不稳定区域，回退重扫

### 6. 多目标 Pareto 优化

不是单一评分。使用 12 个维度交叉验证，在稳定性、活性保持、序列质量、可开发性和多样性之间找到非支配前沿。

## 七、本案例的设计速览

```
输入: "帮我设计蛋白酶K，保持酶活性和底物选择性不降低的同时，提高热稳定性"
    │
    ├─ Stage 0: 4轮互动 → 目标精确化为 "Tm +15-20°C, 保持广谱选择性"
    │
    ├─ Stage 1: 6通道并行 → 检索78篇PRK+30篇枯草杆菌蛋白酶文献
    │         关键证据: D260V(12.4×), R218S(活性+稳定性双提升),
    │         CM16(沸水稳定16突变模板), 枯草杆菌蛋白酶突变不迁移
    │
    ├─ Stage 2: 4条策略对比 → 用户选策略4(全集成)
    │         管道: 5阶段, 7硬过滤+12排名指标, 4个自适应决策门
    │
    └─ Stage 3: 12工作包 → 预估400-800 GPU-hours
              → 能力解析: PyRosetta ✓, FoldX ✗(跳过), AF2 ✓, OpenMM待装
              → 等待用户批准执行
```
